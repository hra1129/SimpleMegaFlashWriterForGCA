# SMFWriter — Simple Mega Flash Writer (Windows コマンドライン版)

MSXPLAYer **Game Cartridge Adapter** を USB で PC に接続し、**Simple Mega Flash
カートリッジ** へ ROM イメージを書き込むための Windows コマンドラインツールです。

- 対象アダプタ: [MSXPLAYer_GameAdapter](https://github.com/v9938/MSXPLAYer_GameAdapter)
  (USB CDC 仮想 COM ポート、テキストコマンド方式)
- 対象カートリッジ: [MSX_SimpleMegaFlash](https://github.com/v9938/MSX_SimpleMegaFlash)
  (Flash ROM: Microchip SST39SF040A 4Mbit)
- マッパーはコマンドラインオプションで指定します: `/A8` (ASCII8) / `/A16` (ASCII16) / `/K8` (KONAMI8K)

書き込み手順は、カートリッジ付属の MSX 用書き込みプログラム SW.COM と同一の
アルゴリズム (バンクセレクト → JEDEC アンロック → バイトプログラム →
再セレクト → 読み戻しポーリング) を、アダプタのスクリプトエンジン (BSCR) で
デバイス側実行する方式です。書き込み後は全バイトのベリファイを行います。

## ビルド方法

Visual Studio 2022 で `SMFWriter.sln` を開き、ビルドしてください。

- 構成: Debug / Release、いずれも **x64**
- ツールセット: v143、C++17、追加ライブラリなし (Win32 API + setupapi.lib のみ)
- ソースは UTF-8 (プロジェクトに `/utf-8` オプション設定済み)

生成物は `x64\Release\SMFWriter.exe` などに出力されます。

## 使い方

### 事前準備 (カートリッジ側スイッチ)

ツール側ではスイッチの検出・制御はしません。書き込み前に手動で設定してください。

| スイッチ | 設定 |
| --- | --- |
| SW2 (バンクモード) | 書き込むマッパーの位置 (`/A8` なら ASCII8 の位置) |
| SW1 (ROM クリッピング) | **4Mbit 位置 (真ん中)** |

SW1 を 4Mbit 位置にするのは書き込み時の前提です。特に KONAMI8K モードでは、
SW1 が 4Mbit 位置でないと CPLD 仕様で ROM 自体が無効化されます。
書き込み後に実機で使う際は、必要に応じて SW1 を ROM サイズに合った位置へ
戻してください (例: 256KB の ROM なら 2Mbit 位置)。

### 接続

1. Game Cartridge Adapter を USB で PC に接続します。
2. Simple Mega Flash カートリッジをアダプタのスロットに挿します。
3. コマンドプロンプトで SMFWriter を実行します。

COM ポートは自動検出します (USB COM ポートを列挙し、HVER コマンドへの応答で
アダプタを識別)。複数候補がある場合や自動検出できない場合は `/P:COMx` で
明示指定してください。

### コマンドライン

```
SMFWriter <ROMファイル> /A8|/A16|/K8 [オプション]
```

| オプション | 意味 |
| --- | --- |
| `/A8` | マッパー: ASCII8 (最大 512KB) |
| `/A16` | マッパー: ASCII16 (最大 512KB) |
| `/K8` | マッパー: KONAMI8K (最大 128KB) |
| `/P:COMx` | アダプタの COM ポートを指定 (例: `/P:COM5`)。省略時は自動検出 |
| `/S:n` | スロット番号 1 または 2 (既定: 1) |
| `/Y` | 消去前の確認プロンプトを省略 |
| `/NV` | 書き込み後のベリファイを省略 |

マッパーオプションは必須です。ROM ファイルとマッパーの整合が取れない場合
(サイズ超過など) は、書き込み前にエラーで停止します。

### 実行例

```
> SMFWriter game.rom /A8
> SMFWriter game.rom /A16 /P:COM5
> SMFWriter gm2.rom /K8 /Y
```

### 処理の流れ

1. ROM ファイルの読み込みとサイズチェック
2. アダプタ接続 (自動検出または /P 指定)、HVER 表示
3. カートリッジ挿入確認 (SCHK)。未挿入なら挿入を促します
4. スロット電源 ON (SPON) とリセット (SRST)
5. **Flash ID 確認** — SST39SF 系 (Maker=BFh) でなければ消去せずに中止します
6. 確認プロンプト (/Y で省略可)
7. チップ消去 (完了は読み戻しでポーリング確認)
8. バンク単位の書き込み (0xFF のバイトは消去状態と同じため自動で省略)
9. ベリファイ (全バイト読み戻し比較、/NV で省略可)
10. スロット電源 OFF (SPOFF)

エラー時は、失敗したバンク番号やオフセットを表示して中止します。
書き込みに失敗した場合は、スイッチ設定 (SW2 の位置、SW1=4Mbit) と
カートリッジの接触を確認してください。

## 注意点

- **KONAMI8K モードの容量は 128KB まで** です (カートリッジの仕様)。
  128KB を超える ROM は `/K8` では書き込めません。
- ROM サイズがバンク境界 (8KB / 16KB) の倍数でない場合、不足分を 0xFF で
  埋めてから書き込みます (画面に注意表示が出ます)。
- 書き込み中はカートリッジを抜かないでください。電源 OFF (SPOFF) は
  正常終了時・異常終了時ともにツールが行います。
- SRAM の内容は保持されません (チップ消去で Flash のみ消去します。
  SRAM は消去対象ではありませんが、書き込み作業中のバンク操作は
  SRAM 領域に触れない設計です。それでも大切なセーブデータがある場合は
  事前にバックアップしてください)。
- アダプタのファームウェアは、公式サンプルが対象とする世代
  (スクリプトエンジン搭載) を前提としています。極端に古いファームウェアでは
  動作しない可能性があります。

## 技術メモ (実装の根拠)

- Flash コマンドアドレスは CPLD (S_MEGA_CON2) がマッパーと無関係に固定
  デコードします: スロット 0x3555 → Flash 0x5555、スロット 0x2AAA → Flash 0x2AAA。
  アンロック/消去/ID の各シーケンスはこの2アドレス宛てに発行します。
- バンクセレクトと書込ウィンドウ (SW.COM と同一):
  - ASCII8: レジスタ 0x7800、ウィンドウ 0xA000–0xBFFF (8KB)
  - ASCII16: レジスタ 0x7000、ウィンドウ 0x8000–0xBFFF (16KB)
  - KONAMI8K: レジスタ 0xA000、ウィンドウ 0xA000–0xBFFF (8KB)
- KONAMI8K ではウィンドウ前半 (0xA000–0xAFFF) への書込でもバンクレジスタが
  データ値で上書きされるため、SW.COM と同様にバイト毎に
  「セレクト → 書込 → 再セレクト → ポーリング」の順序を守っています。
- スクリプトは 512 バイト単位で生成し、BRCV でアダプタ内バッファへ転送後、
  BSCR で実行します。ポーリング上限は LSCR で最大値に設定しています。
